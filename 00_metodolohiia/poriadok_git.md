## Репозиторій і доступ

Робоча папка: D:\BOOKS\PSYCHO. Гілка: main. Origin: https://github.com/Erchard/PSYCHO.git. Репозиторій публічний. Використовується підтверджений акаунт Erchard через HTTPS і Git Credential Manager; секрети не записуються в проєкт.

GitHub API підтвердив ім’я акаунта й право push перед першою відправкою. Глобальні налаштування інших акаунтів не змінено; ім’я облікового запису для github.com налаштовано локально в цьому репозиторії. Автор Git-коміту й акаунт автентифікації — різні речі; належність доступу перевіряється окремо.

Початковий remote-коміт із MIT LICENSE збережено; історії об’єднано без force push.

## Цикл кожного змістовного кроку

1. Прочитати AGENTS.md, журнал і план. Перевірити status; не перезаписувати сторонні зміни.
2. За потреби fetch та перевірити віддалені зміни перед редагуванням.
3. Виконати один перевірюваний результат; оновити джерела, навігацію й журнал.
4. Переглянути diff, перевірити UTF-8, локальні посилання й відповідні змістові критерії. Перевірити відсутність секретів та неналежних персональних даних.
5. Додати саме файли цього кроку й зробити описовий commit. Великі етапи ділити на менші коміти, що мають самостійний зміст.
6. Виконати push origin main. Після першого налаштування upstream можна використовувати git push.
7. Звірити локальний HEAD із віддаленим refs/heads/main; перевірити чистоту робочої папки. Зафіксувати статус без самопосилального запису hash того самого коміту.
8. Якщо push не вдався, повідомити точну причину. Локальний commit не називати опублікованим; не переходити мовчки до накопичення несинхронізованих етапів.

## Межі й історія

Не використовувати force push, reset із втратою змін або заміну ліцензії для рутинної синхронізації. Конфлікти вирішувати зі збереженням змісту й перевіркою.

Дослідницькі матеріали й наявний архів розмови вже входять до опублікованої бібліотеки за дорученням користувача. Нові дані реальних учасників, секрети або конфіденційні матеріали не додавати до цього публічного репозиторію. Для майбутніх досліджень потрібне окреме належне зберігання.

Завершення текстового кроку не означає завершення емпіричної перевірки описаного методу. Повідомлення коміту й журнал мають відображати фактичний результат.
